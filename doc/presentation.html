ML Pipeline

v3: Deadline-Aware Window Model

The Problem with v2

  • days_to_min target is bimodal: either "now" or ~15 days out
  • Point regression lands in the empty middle → 7.77-day MAE
  • Fixed 30-day horizon — same answer regardless of when you need it

The v3 Solution

  • One model predicts "best achievable drop within k days"
  • User's deadline k becomes a model feature
  • Monotonic constraint: longer window ≥ equal drop
  • Querying at k = days_until_deadline gives personalized answer

How It Works

User: "I need AirPods by July 10"
Days until: k = 13
Model input: features + horizon_days=13
Prediction: best drop within 13d = -2.1%
Threshold: -2.1% > buy_cut (-3%)
BUY "No meaningful drop within 13 days"

Same product, different deadline

User B: k = 30 days
Prediction: best drop = -8.9%
Threshold: -8.9% < wait_cut (-11%)
WAIT "~9% drop likely within 30 days"
Results

v3 Test Set Performance

Window model vs fixed-30d baseline, per deadline horizon

Deadline v3 MAE v2 Baseline MAE Improvement BUY Precision BUY Coverage WAIT Precision
3 days 0.032 0.074 −58% 95.6% 78.9% —
7 days 0.042 0.068 −38% 93.5% 63.5% —
14 days 0.051 0.063 −20% 91.6% 49.5% —
30 days 0.061 0.061 −2% 87.5% 30.6% 66.4%

Key insight: At short deadlines, the model correctly never says WAIT (you can't reliably catch a drop in 3 days) and issues very high-precision BUYs. WAIT only becomes viable at k=30.

What this means

  • 69 products in the backtest basket
  • When we said WAIT, users saved an average of 22.8%
  • 88% of WAIT recommendations were correct
  • v3 is expected to improve short-horizon accuracy further

Precision-First Philosophy

  • We only fire when highly confident (~85% precision)
  • When uncertain, we abstain and fall back to heuristics
  • Users always get an answer — but confident calls are ML-backed
  • Better to say "we're not sure" than be wrong

API

Backend Enhancements

Deadline-Aware Predictions

GET /products/{id}/prediction?deadline=2026-07-15

API picks the v3 row nearest the user's deadline. Falls back to v2 heuristic when v3 rows don't exist. Returns urgency, adjusted verdict, and confidence.

Deals Feed

GET /products/deals

Top 20 high-confidence BUY products near 90-day lows. Powers the "Best Deals Right Now" carousel in the app.

Product Filtering

GET /products?verdict=buy&min_confidence=80&sort_by=confidence

6 new query params: verdict, min_confidence, category, min_price, max_price, sort_by. All additive, non-breaking.

Shared Wishlists

POST /wishlist/share → shareable token
GET /wishlist/shared/{token} → public view
POST /shared/{token}/mark-bought/{id}

Gift mode hides prices. Mark-as-bought prevents duplicates.

How It Works

  • User taps "Set deadline" on the product detail screen
  • Native date picker appears
  • Selected date is sent as ?deadline= to the API
  • API picks the v3 row with the nearest horizon
  • Verdict adjusts: same product, different answer per user
